# بستهٔ آماده‌سازی Chatbox Persian — نصب، PR، همگام‌سازی

**وضعیت:** این یک بستهٔ تغییرات سورس و CI است، نه فایل exe ساخته‌شده، نه Release منتشرشده و نه Pull Request ارسال‌شده. بر اساس ZIP ارسالی کاربر تهیه شده است. سورس ZIP پوشهٔ حیاتی `release/app` و تاریخچهٔ `.git` ندارد؛ برای بسته‌بندی و ادغام باید روی **نسخهٔ اصلی موجود در D:\\Project\\ChatBox** یا یک Git clone کامل اعمال شود.

## ۱) اعمال بدون پاک‌کردن تغییرات فارسی

1. از پروژهٔ ویندوزی خود کپی پشتیبان بگیرید. ZIP این بسته را Extract کنید.
2. روی کامپیوتری که سورس کامل `release/app/package.json` و `release/app/package-lock.json` و Git دارد، در PowerShell (فقط مرحلهٔ توسعه، نه استفاده از برنامه)، از داخل پوشهٔ این بسته اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File .\Apply-Persian-Changes.ps1 -ProjectPath 'D:\Project\ChatBox'
```

اسکریپت ابتدا SHA256 فایل‌ها را با ZIP ارسالی مقایسه می‌کند، سپس از فایل‌های فعلی نسخهٔ پشتیبان جداگانه می‌گیرد و فقط تغییرات همین بسته را اعمال می‌کند. اگر فایل‌ها از زمان تهیهٔ ZIP تغییر کرده باشند، اجرا بدون overwrite متوقف می‌شود. سایر تغییرات فارسی/RTL دست‌نخورده می‌مانند.

## ۲) نسخهٔ اصلی جدید را بدون حذف RTL دریافت کنید

تغییرات فعلی پروژه را در یک branch شخصی به Git **commit** کنید (از `git add .` یا force push بدون بررسی استفاده نکنید). سپس وقتی `git status` تمیز شد:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\persian\sync-upstream.ps1
```

این اسکریپت قبل از ادغام یک branch پشتیبان می‌سازد، `upstream/main` را fetch می‌کند و با **merge عادی** جلو می‌رود؛ در صورت conflict متوقف می‌شود. هیچ `reset --hard` و force push انجام نمی‌دهد. پس از ادغام، تست RTL و بررسی نسخه را انجام دهید و خودتان merge commit را ثبت کنید.

**آخرین انتشار رسمی بررسی‌شده در 2026-11-08: نسخهٔ 1.24.2.** نسخهٔ کد ZIP ارسالی 1.24.0 است. تا زمانی که واقعاً کد 1.24.2 در Git عمومی موجود نباشد و با موفقیت ادغام نشده باشد، نسخهٔ شخصی را 1.24.2 معرفی نکنید. `stamp-version.mjs` با نسخهٔ ناسازگار عمداً خطا می‌دهد.

برای بررسی خودکار روزانه، workflow `Chatbox Persian - Propose upstream changes without losing RTL` روی فورک، یک PR به **خود فورک** می‌سازد. انتشار خودکار بدون تأیید و تست ندارد. اگر conflict رخ دهد PR ساخته نمی‌شود و branch سالم می‌ماند.

## ۳) نصاب ویندوز و آپدیت شخصی

1. پروژهٔ کامل اصلاح‌شده را به **فورک عمومی GitHub خودتان** push کنید؛ مطمئن شوید فایل‌های داخل `release/app` هم داخل repository هستند. URL فورک شما هنوز در اختیار این محیط نیست.
2. در GitHub → Actions، workflow `Chatbox Persian - Windows installer and personal updates` را با `Run workflow` اجرا کنید.
3. نسخهٔ ورودی باید مطابق سورس ادغام‌شده باشد؛ برای مثال فقط **بعد از ادغام واقعی upstream 1.24.2** مقدار `1.24.2-persian.1` بزنید و `publish=false` را بگذارید.
4. با موفقیت تست‌ها و ساخت، نصاب در بخش **Artifacts** همان اجرا به شکل فایل ZIP قابل دانلود خواهد بود؛ EXE داخل آن است. فایل را روی ویندوز واقعی نصب و اجرا کنید و فارسی، انگلیسی، کد، لینک و حفظ داده‌ها را تست کنید.
5. سپس با نسخهٔ جدیدتر و `publish=true`، GitHub Release شخصی بسازید. `latest.yml` و `.blockmap` و EXE با هم منتشر می‌شوند تا برنامه نصب‌شده نسخه‌های جدید شخصی را دریافت کند.

نکته: مخزنِ Release باید عمومی باشد؛ هیچ توکن GitHub نباید در EXE قرار بگیرد. نسخه‌های شخصی مانند `1.24.2-persian.1` و سپس `1.24.2-persian.2` باید روند افزایشی داشته باشند. نسخهٔ نصاب بدون گواهی امضای ویندوز ساخته می‌شود و امکان هشدار SmartScreen وجود دارد. داده‌ها و آپدیت باید با نصب واقعی N به N+1 آزمایش شوند.

فونت وزیرمتن v33.003 و مجوز OFL آن **در زمان build** از منبع رسمی دریافت و در برنامه جای‌گذاری می‌شوند؛ بعد از نصب، نمایش فونت نیازی به اینترنت ندارد. بدون دریافت واقعی فونت، ساخت باید خطا دهد؛ هیچ جایگزین جعلی استفاده نشده است.

## ۴) PR پروژهٔ اصلی

پروندهٔ `scripts/persian/PR-UPSTREAM-DRAFT.md` شرح تغییرات قابل ارائه به upstream را دارد. PR بازِ #3865 را ابتدا بخوانید: <https://github.com/chatboxai/chatbox/pull/3865>. ارسال PR جدید به مخزن اصلی، نیازمند branch روی فورک و مجوز GitHub است. تنظیمات شخصی/کانال آپدیت را نباید در PR اصلی بفرستید. تا وقتی URL واقعی PR ایجاد نشده، «ارسال شد» محسوب نمی‌شود.

## تست واقعی انجام‌شده

- `node --test scripts/persian/*.test.mjs`: چهار بررسی کد، موفق.
- نحو فایل‌های JS (`node --check`): موفق.
- نصب وابستگی‌ها، Vitest، typecheck، build ویندوز، تست بصری و انتقال N به N+1: **در این محیط اجرا نشده‌اند**.

## مرزهای ایمنی

- `release/app` و `.git` در ZIP ارسالی موجود نیستند. این بسته آن‌ها را جعل یا جایگزین نمی‌کند.
- نه اتصال push به حساب کاربر وجود دارد و نه گواهی امضا. هیچ PR/Release واقعی ارسال نشده است.
- اجرای `Apply-Persian-Changes.ps1` فقط فایل‌های موجود در manifest را ویرایش می‌کند و از نسخهٔ قبلی بکاپ تهیه می‌کند.
- هر بار پیش از Release، کد رسمی را ادغام و بررسی کنید؛ صرف افزایش عدد نسخه به معنای اعمال کد جدید نیست.
